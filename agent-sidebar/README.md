# Agent sidebar для Ghostty (форк, PoC)

Ветка `agent-sidebar` = Ghostty **v1.4.0** + боковая панель с вертикальными
вкладками и статусами агентов, по мотивам сайдбара Intelligent Terminal 0.3.

> **Статус: собирается, но ни разу не запускался.** Код написан в
> Linux-контейнере без Mac. Сборка проходит на macOS-машине GitHub Actions
> (workflow `agent-sidebar`, Xcode 26), то есть код компилируется. Как сайдбар
> выглядит и ведёт себя, никто ещё не видел. Хук-скрипт и установщик хуков
> проверены запуском. Места, где вероятнее всего проявятся проблемы при
> работе, перечислены ниже.

## Что есть

Слева в каждом окне терминала панель «Tabs»:

- вертикальный список вкладок окна: иконка, заголовок, под ним метаданные;
- иконка агента (✳ у Claude Code), во время работы агента вместо неё крутилка;
- статус агента: `Working…` / `Needs you` (с текстом запроса) / `Done` / `Idle`;
- оранжевая точка у вкладки, которая ждёт вас или звенит (bell);
- текущая папка, git-репозиторий, ветка, число изменённых файлов;
- меню настроек (иконка с ползунками): «Agents only», «Recent agent sessions»,
  набор метаданных, «Hide native tab bar»;
- поиск по вкладкам, кнопка «+» (новая вкладка), крестик при наведении;
- правый клик по вкладке: переименовать, скопировать папку, закрыть, закрыть
  остальные;
- раздел «Recent agent sessions»: последние сессии Claude Code из
  `~/.claude/projects`, клик открывает новую вкладку с `claude --resume <id>`;
- ширина меняется перетаскиванием разделителя, кнопка в шапке сворачивает
  панель в узкую полоску;
- кнопка ✨ в шапке открывает справа **агентскую панель** (чат с агентом, см.
  ниже);
- полоса внизу сайдбара, когда команда в выбранной вкладке завершилась с
  ошибкой: «Command failed — Fix» → «Analyzing…» → «Fix ready — Run».

Пункты меню View и горячие клавиши:

| Действие | Клавиши |
|---|---|
| Show Tab Sidebar | ⌃⌘S |
| Show Agent Tabs Only | ⌃⌘G |
| Go to Next Tab Needing Attention | ⌃⌘A |
| Open Agent Pane | ⌃⌘P |
| Fix Last Error | ⌃⌘. |

Что из этого проверено: сборка и внешний вид сайдбара (по скриншотам из CI,
ветка `agent-sidebar-screenshots`). Клики, горячие клавиши, перетаскивание,
статусы от настоящего Claude Code и агентская панель на живом Mac ещё не
проверялись.

## Агентская панель и исправление ошибок

Чат с агентом и исправление ошибок делает WTA — агентская часть Intelligent
Terminal от Microsoft, портированная на macOS в репозитории
[AgentTerm](https://github.com/IRadJaI/AgentTerm) (ветка `macos-port`).
Ghostty в этой связке — терминал: форк открывает для WTA управляющий сокет.

Установка (один раз):

```bash
git clone -b macos-port https://github.com/IRadJaI/AgentTerm.git ~/src/AgentTerm
cd ~/src/AgentTerm
tools/wta/macos/build.sh                       # собирает wta и wtcli (нужен Rust)
mkdir -p ~/bin && ln -sf "$PWD/tools/wta/macos/wta-ghostty" ~/bin/wta-ghostty
# ~/bin должен быть в PATH вашего zsh (проверьте: `which wta-ghostty`)
```

Нужны также Node.js (`npx`) и залогиненный Claude Code.

Использование:

1. В Ghostty нажмите ✨ в шапке сайдбара (или ⌃⌘P). Справа откроется панель
   с чатом. Первый запуск занимает 10–30 секунд: скачивается адаптер Claude.
2. Пишите агенту. Он видит соседнюю панель с shell и может предложить
   выполнить в ней команду: появится карточка `[ Run command ]`, Enter
   выполняет.
3. Если команда в shell завершилась с ошибкой, внизу сайдбара появится
   «Command failed — Fix». Кнопка (или ⌃⌘.) отправляет ошибку агенту, ответ
   приходит в агентскую панель. Это работает, пока в этой вкладке открыта
   агентская панель и включена shell-интеграция Ghostty (по умолчанию для
   zsh, bash и fish включена).

Если панель открылась с сообщением об ошибке, оно говорит, чего не хватает
(не найден `wta-ghostty`, не собран `wta` и т. п.).

Команда запуска панели хранится в настройке `AgentSidebar.agentPaneCommand`
(по умолчанию `/bin/zsh -lc 'exec wta-ghostty helper'`).

### Управляющий сокет

Форк слушает Unix-сокет `$TMPDIR/ghostty-agent-<uid>/<bundle-id>.sock`
(права 0600, каталог 0700) и передаёт путь дочерним процессам в переменной
`GHOSTTY_AGENT_SOCKET`. Через него доступны: список окон, вкладок и панелей,
чтение текста панели, сплит и новая вкладка, ввод текста, фокус и закрытие,
поток событий (в том числе «команда завершилась с кодом N»). Любой процесс
вашего пользователя может подключиться к сокету и, например, ввести текст в
терминал — так же, как это позволяет AppleScript-интерфейс самого Ghostty.

## Готовая сборка из GitHub Actions

Каждый пуш в ветку собирает Debug-приложение. Скачать его можно со страницы
запуска workflow `agent-sidebar` (раздел Artifacts,
`Ghostty-agent-sidebar-debug`): <https://github.com/IRadJaI/ghostty/actions/workflows/agent-sidebar.yml>

Приложение подписано только ad-hoc подписью, без сертификата разработчика,
поэтому после распаковки снимите карантин:

```bash
unzip Ghostty-agent-sidebar-debug.zip      # внутри ещё один zip с Ghostty.app
xattr -dr com.apple.quarantine Ghostty.app
open Ghostty.app
```

Это Debug-сборка: у неё свой bundle id (`com.mitchellh.ghostty.debug`), она
не мешает установленному Ghostty, работает медленнее и показывает жёлтую
плашку.

## Сборка на Mac

Нужны Xcode 26 (с macOS 26 SDK и Metal Toolchain) и Zig 0.17.x — это
требования самого Ghostty 1.4, см. `HACKING.md`.

```bash
git clone -b agent-sidebar https://github.com/IRadJaI/ghostty.git
cd ghostty

# 1. Ядро (GhosttyKit). Долго только в первый раз.
zig build -Demit-macos-app=false

# 2. Приложение. Debug-сборка имеет отдельный bundle id
#    (com.mitchellh.ghostty.debug) и не мешает установленному Ghostty.
xcodebuild -project macos/Ghostty.xcodeproj -scheme Ghostty \
  -configuration Debug SYMROOT="$PWD/macos/build" build

open macos/build/Debug/Ghostty.app
```

Debug-сборка медленная и показывает жёлтую плашку — это штатное поведение
Ghostty. Для повседневного использования собирайте `-configuration
ReleaseLocal`; у неё bundle id обычного Ghostty, поэтому официальный Ghostty
перед запуском надо закрыть.


## Статусы Claude Code (хуки)

Без хуков сайдбар только узнаёт агента (по процессу в терминале и по
заголовку). Статусы «работает / ждёт вас / готово» приходят из хуков:

```bash
agent-sidebar/install-claude-hooks.py            # установить
agent-sidebar/install-claude-hooks.py --print    # показать, что будет записано
agent-sidebar/install-claude-hooks.py --remove   # убрать
```

Установщик дописывает шесть хуков в `~/.claude/settings.json` (существующие
хуки не трогает, перед изменением делает резервную копию) и копирует скрипт в
`~/.ghostty-agents/bin/ghostty-agent-hook`. После установки перезапустите
открытые сессии Claude Code.

Как это работает: Claude Code на событиях (`UserPromptSubmit`, `PreToolUse`,
`Notification`, `Stop`, `SessionStart`, `SessionEnd`) запускает скрипт. Тот
находит tty терминала и пишет `~/.ghostty-agents/status/<tty>.json`. Сайдбар
раз в секунду читает эти файлы и сопоставляет их с вкладками по tty. Наружу
ничего не отправляется.

## Что изменено в коде Ghostty

Правки существующих файлов upstream (всё остальное — новые файлы):

| Файл | Что |
|---|---|
| `macos/Sources/Features/Terminal/TerminalController.swift` | корневой вид окна обёрнут в `AgentSidebarContainer`; начальный размер окна учитывает сайдбар |
| `macos/Sources/App/AppDelegate.swift` | запуск управляющего сокета при старте приложения |
| `macos/Sources/Ghostty/Ghostty.App.swift` | код выхода завершившейся команды передаётся в сокет как событие |

Новые файлы в `macos/Sources/Features/Agent Sidebar/`:

| Файл | Что |
|---|---|
| `AgentSidebarTypes.swift` | типы и разбор данных (хуки, git, сессии), только Foundation |
| `AgentSidebarModel.swift` | общий на приложение снимок вкладок, определение агентов, действия |
| `AgentSidebarView.swift` | интерфейс на SwiftUI |
| `AgentSidebarMenu.swift` | пункты меню View и горячие клавиши |
| `AgentControlServer.swift` | управляющий сокет |
| `AgentSidebarDemo.swift` | образцы данных для скриншотов (`GHOSTTY_AGENT_SIDEBAR_DEMO=1`) |

Вне приложения: `agent-sidebar/` (хук-скрипт, установщик хуков, сценарий
скриншотов, этот README) и `.github/workflows/agent-sidebar.yml`.

Файл проекта Xcode не менялся: папка `Sources` подключена как синхронизируемая,
новые файлы попадают в сборку сами. Ядро на Zig не тронуто. Быстрый терминал
(Quick Terminal) сайдбар не получает.

## Известные проблемы и что проверить глазами

1. **Полоса заголовка над сайдбаром.** Фон сайдбара начинается под заголовком
   окна, а не идёт на всю высоту, как у Finder. Две попытки это исправить не
   сработали.
2. **Прозрачность.** Фон — системный материал боковой панели
   (`NSVisualEffectView`, `.sidebar`, behind-window). На серверах CI macOS
   не рисует прозрачность вообще, поэтому как это выглядит, видно только на
   настоящем Mac.
3. **Скрытие родной полосы вкладок** (`applyNativeTabBarVisibility`).
   Полоса вкладок — приватная часть AppKit, а в CI открыто одно окно без
   вкладок. Если полоса не скрывается или ведёт себя странно, особенно при
   `macos-titlebar-style = tabs`, выключите «Hide native tab bar» в меню
   сайдбара.
4. **Переключение вкладок.** Каждая вкладка — отдельное окно macOS со своей
   копией сайдбара. Данные общие, но возможны мелкие визуальные артефакты
   (например, сбрасывается прокрутка списка).
5. **Распознавание агента по процессу** (`proc_name`). Если Claude Code
   запущен через `node`, без хуков он распознаётся только по заголовку «✳».
6. **Размер окна.** Ширина сайдбара добавляется к ширине нового окна, чтобы
   терминал сохранял `window-width`. Для панели, вытащенной в новое окно,
   это не учтено.

## Чего пока нет

- перетаскивания вкладок в сайдбаре, закрепления, превью содержимого;
- статусов для агентов, кроме Claude Code (остальные только распознаются);
- скрытия агентской панели с сохранением сессии (закрытие панели завершает
  чат);
- автоматических тестов, кроме запуска приложения и скриншотов в CI.

## Синхронизация с upstream

Патч задевает четыре места upstream-кода (по 1–5 строк в трёх файлах),
поэтому переход на следующую версию — это `git rebase` ветки на новый тег.
Конфликты возможны только в этих местах; они помечены комментарием
`agent-sidebar`.
